# Nico

Nico turns learning sources into reusable knowledge, quizzes, lessons, project work, and reports. The working MVP is a server-rendered web app at `/app`.

## What works today

- Accounts, sessions, roles, capability profiles, and project membership.
- Text notes/briefs/transcripts and PDF upload.
- PDF text is read in the browser with vendored pdf.js; `pdftotext` optionally re-checks it on the edge. Page numbers are kept on chunks.
- The original PDF is stored outside the webroot with MIME, size, sha256, original filename, and an authenticated download route.
- Knowledge search can run in two modes: lexical keyword ranking, or hybrid ranking that adds Ollama embeddings. The API reports which mode it used.
- Quizzes and lessons can be generated by the deterministic template engine or by the local Ollama chat model, with strict JSON validation and template fallback.
- Quiz attempts are private, scored on the server, and rendered in a click-next flow.
- Projects have tasks, milestones, dependencies, due dates, best-fit and manual assignment, status changes, and artifact links.
- Events and hackathons have RSVP/waitlists, teams, and submissions.
- Reports cite sources, tasks, artifacts, and activities.
- CSRF-protected web forms, ownership/membership checks, and 403/404 pages.

## What is not built yet

- OCR for scanned PDFs, images, audio, video, and link ingestion.
- Background job/worker processing with live status/progress for indexing and generation.
- Source-edit/reprocess flow with re-indexing.
- cPanel storage driver; uploads use a local `STORAGE_PATH` placeholder.
- Blog/PWA delivery and full publishing flow.

[`ARCH.md`](ARCH.md) and [`FLOW.md`](FLOW.md) describe the intended edge/compute architecture. The current MVP is deliberately synchronous and local-first.

## Quick start

```bash
./dev.sh db:start     # MariaDB 10.11 container
cd edge && cp .env.example .env && cd ..
./dev.sh migrate      # schema, currently migrations 001–007
./dev.sh serve        # http://127.0.0.1:8080 (20 MB upload limit)
./dev.sh test         # 30 Sprint 1 + 47 M0 + 74 M1–M8 checks
```

Register at `http://127.0.0.1:8080/register`, then open `/app`. `./dev.sh stop` stops the dev server.

## Demo path

1. Add a text note or upload a PDF from **Library → Add source**.
2. Search the library for a phrase from the source. When Ollama is enabled, results are marked `hybrid`; otherwise `lexical`.
3. From the source page, generate a quiz or lesson.
4. Create a project, add tasks, and try best-fit or manual assignment.
5. Add an event or hackathon, RSVP, form a team, and submit work.
6. Generate a report and follow its citations back to the sources and work.

## How each module is broken down

### M0 — Platform

- **Does:** provides accounts, sessions, roles, migrations, shared entities, permissions, the durable job queue, and the HMAC worker contract.
- **Inputs:** configuration, user credentials, migration files, worker requests.
- **Pieces:** auth/session layer, database/migrator, project/membership repositories, task and artifact repositories, queue, worker API.
- **Outputs:** authenticated sessions, shared records, versioned artifacts, queued jobs.
- **State:** built and verified (30/30 + 47/47). The worker protocol is tested even though day-to-day generation is currently synchronous.

### M1 — Injector / Ingestion

- **Does:** accepts a source, validates it, stores the original safely, and extracts text.
- **Inputs:** pasted text or a PDF upload.
- **Pieces:** browser pdf.js extractor, optional edge `pdftotext` re-check, storage abstraction, PDF ingestion service, checksum/MIME/size validation.
- **Outputs:** a `resources` row, raw `files` row, source, and chunks.
- **State:** minimal PDF slice implemented. OCR, images/audio/video, links, and job-driven status/progress are not built.

### M2 — Knowledge

- **Does:** turns extracted text into retrievable, provenance-rich chunks.
- **Inputs:** source text and page segments from M1.
- **Pieces:** chunker with page metadata, lexical ranker, Ollama embedding indexer, vector files, hybrid ranker, scoped authorization, `source_ids` filter.
- **Outputs:** ranked chunks with `source_id`, `resource_id`, `chunk_id`, `ordinal`, `page`, and score.
- **State:** chunking, provenance, scoped retrieval, embeddings, and hybrid ranking are implemented. **Exceptions:** no re-index flow (AC-M2-4) and no async indexing jobs (AC-M2-5). AC-M2-4 is safe only because source text cannot be edited yet; the moment editing is added, re-indexing becomes mandatory.

### M3 — Quizzes & Assessments

- **Does:** generates and scores assessments grounded in sources.
- **Inputs:** M2 chunks for a source or project.
- **Pieces:** quiz generator (template + Ollama), MCQ schema validator, attempt repository, server-side scoring, web quiz pages.
- **Outputs:** versioned quiz artifacts with `source_refs`, private attempt records, feedback.
- **State:** implemented. **Exception:** generation is synchronous, so AC-M3-5 job/failure semantics are not implemented. Only MCQ fill-in-the-blank is supported.

### M4 — Lessons / Notes

- **Does:** builds ordered, click-next learning material from the same chunks.
- **Inputs:** M2 chunks.
- **Pieces:** lesson generator (template + Ollama), step schema validator, progress tracking.
- **Outputs:** versioned lesson artifacts with ordered steps, key points, and source refs.
- **State:** implemented. Same synchronous-generation exception as M3.

### M5 — Live Projects

- **Does:** runs ongoing project workspaces and assigns tasks by capability.
- **Inputs:** users, profiles, capability tags, tasks, project membership.
- **Pieces:** projects, tasks, milestones/dependencies, assignment service, best-fit scoring, manual override, status lifecycle.
- **Outputs:** assigned work, assignment history, project reports' task data.
- **State:** implemented. Assignment history is currently API-only; re-evaluation is caller-triggered.

### M6 — Hackathons & Events

- **Does:** hosts team events and speaker events inside a project workspace.
- **Inputs:** project, users, event/hackathon details.
- **Pieces:** activities, RSVP/waitlist, teams with enforced sizes, submissions, countdown/agenda/materials, manager editing.
- **Outputs:** activity records and versioned M6 artifacts from submissions/notes.
- **State:** implemented.

### M7 — Thesis / Report Composer

- **Does:** composes a per-project report from work and artifacts.
- **Inputs:** tasks, artifacts, sources, activities.
- **Pieces:** report service, citation builder, artifact versioning.
- **Outputs:** versioned report artifacts with citations.
- **State:** implemented; assembly is deterministic. LLM-written reports are not implemented.

### M8 — Delivery

- **Does:** presents everything as web pages in a simple click-next flow.
- **Inputs:** artifacts, attempts, progress, projects, library.
- **Pieces:** server-rendered `/app` views, CSRF-protected forms, 403/404 pages, renderer for quiz/lesson/report/activity pages.
- **Outputs:** the working browser workspace.
- **State:** implemented. Blog/PWA publishing is not built.

## Ollama (local only)

The local `edge/.env` points at the remote Ollama available on the laptop. The key is stored only in that gitignored file and is never committed.

- Embedding model: `nomic-embed-text:latest`
- Chat model: `qwen141:latest`
- API shape: OpenAI-compatible `/v1/embeddings` and `/v1/chat/completions`
- The configured address is a private LAN address, so it works locally but not from cPanel. If Ollama is unreachable, search falls back to lexical ranking and generation falls back to the deterministic templates.
- Tests set `OLLAMA_ENABLED=0` so the suite never depends on the LAN service.

## How ingestion and retrieval work today

```
Choose PDF → browser extracts text per page (pdf.js) → multipart POST with file, text, pages
    → server validates PDF/size → pdftotext re-check when available
    → store file outside webroot → resource + file + source + page-aware chunks in one transaction
    → embed chunks through Ollama when enabled → hybrid search with lexical fallback
```

- Upload cap is 20 MB locally and is also limited by PHP's real `upload_max_filesize` / `post_max_size`.
- Scanned/image-only PDFs are rejected because OCR is not available.
- The edge app has no third-party PHP dependencies. pdf.js is a vendored static JavaScript asset with its Apache-2.0 license.

## Project layout

```

  public/                webroot: index.php, .htaccess, assets/, vendored pdf.js
  src/Ai/                Ollama client and AI interface
  src/Generation/        template + Ollama quiz/lesson/report generation
  src/Knowledge/         sources, chunks, PDF ingestion, vectors, hybrid search
  src/Auth,Http,Projects,Tasks,Activities,...  remaining domain modules
  migrations/            re-runnable schema migrations 001–007
  storage/files/         uploaded PDFs, outside the webroot
  storage/vectors/       local embedding files, outside the webroot
  tests/                 acceptance checks
worker/                  compute preflight script
docs/modules/            active module charters and status
docs/archive/            old sprint specs (not active)
```
